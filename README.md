# Shop API

Shop API - программный интерфейс для взаимодействия с интернет-магазином. Это связующее звено/мост, который позволяет разным программам общаться друг с другом. Работает как набор четких правил и инструкций, позволяя одной системе передавать данные или команды другой, скрывая при этом внутреннее устройство самой программы.

## Архитектура

В API используется архитектурный стиль - REST. Он поддерживает JSON формат данных. Использует одностороннюю связь. 

Через файл docker-compose.yml поднимаются MySQL, Mongo, mongo-express.

Во время запуска приложения через файл main.py создается экземпляр приложения, к нему прикрепляются эндпоинты из routers, также при каждом запуске проверяются созданные таблицы.

В папке db подключаются базы данных. В проекте реализован polyglot persistence, то есть для разных задач были подобраны разные системы управления базами данных. Для пользователей и заказов используется MySQL(система управления реляционными базами данных) так как данные должны иметь четкую взаимосвязь, а для каталога товаров используется MongoDB (NoSQL-система управления базами данных, которая хранит информацию в виде гибких JSON-подобных документов) потому что товары могут иметь разные критерии (например, техника будет иметь показатель "мощность", а одежда - "размер"). 

В папке routers собраны эндпоинты каталога(MongoDB), пользователей(MySQL), заказов(MySQL + MongoDB).

## Технологии
- FastAPI
- MongoDB (Motor)
- MySQL (aiomysql)
- Docker Compose

## Запуск

Для запуска введите поочередно в терминал следующие команды:
1. docker compose up -d
2. uvicorn main:app --reload

## Что было сложного

В процессе написания проекта возникли некоторые сложности:
1. Была сложность с ObjectId, так как это особый тип MongoBD с которым не умеет работать FastAPI. Это получилось решить через преобразование в строку, через функцию serialize_product;
2. Изначально для закрытия соединения использовала метод close(), но после нашла информацию, что для асинхронных функций лучше использовать "await conn.ensure_closed()" - однако использование первого варианта не является ошибкой;
3. В самом начале для product_id в таблице order_items использовала тип BIGINT (предполагала, что id будет большим числом), но после выяснился момент с особым типом ObjectId в MongoDB поэтому пришлось изменить тип VARCHAR(50).
